# 資本支出 IRR 效益追蹤系統

## 目前版本

`index.html` 是模組化應用的 HTML 外殼，依序載入 `src/` 下的工具、核心、引擎、元件與頁面模組，並載入 `demo/seed.js` 範例資料。修改這些模組會影響實際執行的應用程式。

應用程式以原始單檔版本的 Excel 解析與 IRR 演算法為基準，並透過模組 API 提供專案概覽、年度回報、通知、審計及備份功能。`src/engine/irr-engine.js` 是公式及 IRR 計算核心；`src/engine/compute.js` 提供應用層介面。

## 快速開始

可直接在現代瀏覽器開啟 `index.html`。也可在 `outputs/` 目錄啟動靜態伺服器：

```bash
python -m http.server 8000
```

接著開啟 `http://localhost:8000`。此應用程式沒有建置步驟，也沒有外部執行期相依套件。

Excel `.xlsx` / `.xlsm` 解壓縮使用瀏覽器的 `DecompressionStream` API；若瀏覽器不支援，請改用支援此 API 的新版瀏覽器。

## 功能

- 上傳 Excel，解析 `IRR` 工作表並建立追蹤專案。
- 檢視專案年度效益、成本、回報狀態、原提報與實際 IRR。
- 編輯年度回報並重新計算 IRR 與回收年限。
- 年度回報未輸入的數值會以 `0` 保存；只有項次、沒有描述且基準值全為零的 Excel 占位列會略過。
- 依搜尋條件、廠區、狀態篩選及排序專案。
- 調整系統日期以測試年度提醒排程。
- 檢視通知及操作紀錄。
- 匯出或匯入 JSON 備份。
- 「操作紀錄」及「備份 / 恢復」需先登入管理者通行碼；第一次使用時由管理者設定。

通知功能僅在應用程式內產生通知紀錄，不會實際寄送 Email。

## 範例資料

首次啟動且沒有已儲存專案時，應用程式會從 `demo/seed.js` 建立一筆 `P001` 專案，計算 baseline IRR 後保存到瀏覽器儲存空間。`demo/seed.json` 是可閱讀的範例資料副本。

若要在已使用的瀏覽器中查看新範例，可先從「備份 / 恢復」匯出現有資料，再清除該瀏覽器中此頁面的網站資料；重新開啟後會重新初始化範例專案。清除網站資料會刪除本機資料，請先確認備份完成。

## 資料保存與隱私

專案資料保存在瀏覽器的 `localStorage`，儲存鍵為 `irr-tracker-v4`。Excel 檔案在瀏覽器本機解析，不會由此應用程式上傳；資料不會自動同步到其他裝置或瀏覽器，也不會因為程式更新而自動備份。

使用不同瀏覽器、瀏覽器設定檔或網站來源（例如不同網域或連接埠）時，看到的資料可能不同。請定期匯出 JSON 備份。匯入備份會取代目前資料，操作前務必先備份。

## 常見問題

### 專案清單沒有範例資料

範例只會在資料庫沒有專案且尚未標記初始化時建立。請確認使用的是 `outputs/index.html`，並檢查目前瀏覽器來源是否已有資料；若要重置，先匯出備份，再清除該來源的網站資料。

### Excel 無法解析

請確認檔案為 `.xlsx` 或 `.xlsm`，且包含 `IRR` 工作表。檔案解壓需要瀏覽器支援 `DecompressionStream`；不支援時請更新瀏覽器。

### 換電腦後看不到資料

資料只存在原瀏覽器的 `localStorage`。請在舊裝置匯出 JSON 備份，再於新裝置使用「備份 / 恢復」匯入。

### 不要公開部署真實資料

應用程式沒有登入或伺服器端存取控制。雖然資料預設保存在使用者的瀏覽器，但公開網站上的應用程式不能視為具備企業級存取保護；請勿把敏感資料部署在共用或公開的瀏覽器環境。

「操作紀錄」及「備份 / 恢復」頁面有前端通行碼門檻，通行碼保存在瀏覽器 `localStorage`，登入狀態僅維持於目前分頁。這不是帳號或伺服器端權限控制；可使用開發者工具或清除網站資料繞過，不能用來保護機密資料。初次設定應由管理者在受控裝置完成。若需要真正的個人帳號、角色權限或防止直接存取，必須加入伺服器端驗證。

審計紀錄資料仍保存在可由使用者控制的 `localStorage`，不是防竄改的合規稽核儲存系統。操作人欄位目前沒有登入整合，預設為匿名使用者。
